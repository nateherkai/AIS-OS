# Six Pillars of the AI Operating System

Jack Roberts' framework for thinking about what components make up a complete personal AI operating system. Used as the organizing structure for the Claude Code OS dashboard.

## The Six Pillars

| Pillar | What It Covers | Pain It Solves |
|--------|----------------|----------------|
| **Models** | Which LLMs in use, what for | Know your stack; stop guessing |
| **Plans** | API vs subscription billing, tier | Stop overpaying; know what's left |
| **Memory** | Local, Obsidian, Pinecone, Supabase, SQL | Find stale memories; know where data lives |
| **Skills** | Skills library, last used, value generated | Kill dead skills; find ROI |
| **Knowledge** | Connected knowledge systems (wiki, RAG, DBs) | See the full graph; find gaps |
| **Connections** | Everything plugged in; integrations | Know what's live and working |

## Why Six?

Each pillar addresses a different class of invisible cost or missed opportunity in AI usage. Together they give a holistic "operating picture" — analogous to how an OS gives a computer a single interface over all its resources.

## Application

The CC-OS dashboard renders each pillar as a data card or visualization. The Dreaming Engine uses all six pillars as inputs for its nightly analysis.

When onboarding clients to this system, Roberts shows ROI per pillar: time saved per skill, cost per model tier, gaps in knowledge coverage.

## Relationship to Bryan's Vault

Bryan's vault/wiki system covers the Knowledge and Memory pillars directly. The `connections.md` in AIS-OS covers Connections. Skills live in `~/.claude/skills/`. Plans and Models are tracked in `connections.md` and the AIS-OS CLAUDE.md.
