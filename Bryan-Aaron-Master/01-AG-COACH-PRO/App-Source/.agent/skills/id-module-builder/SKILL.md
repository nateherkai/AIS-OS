# ID Module Builder Skill

## When to use this skill

- When the user provides a list of items that require visual identification.
- When you need to build out a full ID contest visually (e.g. Floriculture, Vet Science, Meats, Tools) spanning data, images, mapping, and UI screens.

## The 5-Step Process

When invoked to build an ID module, execute the following steps in order.

### Step 1: Data Definition

Analyze the list of items provided by the user. Determine the logical categories/groupings (e.g. Species, Primal, Retail, or just Category).
Write an interface and a fully typed dataset into `lib/data/[name]-id.ts` (e.g., `lib/data/tools-id.ts`).

- Export the primary array: `export const TOOLS: Tool[] = [...]`
- Extract and export unique lists of categories to use as generic dropdown options.
- Create an exported function `generate[Name]Contest(count: number)` that randomly selects requested items and provides all possible categories as distractor options. Reference `lib/data/meats-id.ts` for a mature example of this structure.

### Step 2: AI Image Generation

You MUST generate an image for every single item on the list using your `generate_image` tool.

- **GUARDRAIL:** DO NOT batch generate images in a loop or script. Generate images ONE AT A TIME using individual parallel tool calls (or sequential calls) to prevent locking up the environment.
- **CRITICAL PROMPT RULES:** Your image generation prompt MUST include: "A photographic, highly realistic image of [item name]. Plain white background. No text, no labels, no human hands."
- Images generated by your tool are saved to your current `brain/<conversation-id>/` artifacts directory.
- Once completely generated, run a bash command (`mkdir -p assets/images/[name] && cp /Users/aaronfamilylivestock/.gemini/.../*.png assets/images/[name]/`) to relocate them into the permanent codebase.

### Step 3: Asset Mapping

Once the images are in `assets/images/[name]/`, create a mapping file: `lib/data/[name]-images.ts`.
This file must securely map strings to `require()` calls for immediate local bundling.

```typescript
export const [NAME]_IMAGE_MAP: Record<string, any> = {
  '101': require('../../assets/images/[name]/filename1.png'),
  '102': require('../../assets/images/[name]/filename2.png'),
};
```

### Step 4: UI Scaffolding

Because ID modules rely heavily on visual cues and unique categorical answers rather than basic A/B/C/D multiple choice, they CANNOT use the generic `app/practice/study.tsx` flow.

You must scaffold a dedicated directory: `app/practice/[name]-id/`.

- `index.tsx`: Menu interface providing buttons for Study Mode, Flashcard Mode, and Contest Mode.
- `study.tsx`: Visual teaching module mapping images to their data components.
- `contest.tsx`: The scored ID contest component invoking your `generate[Name]Contest()` logic and rendering image prompts next to categorical dropdowns.
- `list.tsx`: A grid or list view displaying all possible items for quick reference.

*Reference `app/practice/meats-id/` to see a boilerplate example of how these screens interact.*

### Step 5: Master Configuration

Hook the new module into the global app state.

1. Define the contest metadata in `constants/contests.ts`. Ensure `has_practicum: true`.
2. Update the router in `app/contest/[id].tsx`. Since this contest has custom UI, add a conditional to the "Practice Now" or "Study Mode" buttons to route the user specifically to `router.push('/practice/[name]-id')`.
3. Verify Categories and Number of Items (ask user for preferred bounds, e.g., 30 items for contest mode).
